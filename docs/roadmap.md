# Roadmap

This roadmap is intentionally outcome-driven. Each phase should produce a working experience and verifiable evidence before the next layer is expanded.

## Phase 0 — Repository and domain foundation

- [x] Establish repository identity and architectural boundaries.
- [x] Document laboratory, experiment, scientific-integrity, and commercial concepts.
- [x] Establish scientific inquiry sourcebook: method, global history, methods atlas, reproducibility, and open-science foundations.
- [x] Catalogue research-method families across experimental, observational, field, human, mathematical, computational, historical, and synthesis work.
- [ ] Expand historical case studies with primary sources and specialist scholarship across regions and periods.
- [ ] Inspect the current Physics package and identify concrete, reusable simulation capabilities.
- [ ] Inspect FSM_COS, FSM_Execution, Renderer, and Visualize integration contracts.
- [ ] Define the first experiment and its acceptance criteria.

## Phase 1 — First living laboratory

- [ ] Build a navigable laboratory shell with a clear facility / investigation distinction.
- [ ] Implement one end-to-end experiment using existing Physics capabilities.
- [ ] Capture configuration, units, model version, run state, observations, and results.
- [ ] Present the experience through the MicroBundle composition model.
- [ ] Demonstrate repeatability and documented limitations.

**Exit gate:** a user can enter the laboratory, configure an investigation, run or conduct it, inspect meaningful evidence and results, and reproduce or reconstruct the work from its recorded method and provenance.

## Phase 2 — Reusable laboratory tooling

- [ ] Establish versioned laboratory, investigation, method, and experiment definitions.
- [ ] Add reusable instruments, parameter controls, measurement channels, sampling plans, and result views.
- [ ] Add validation states, protocol history, and scientific provenance.
- [ ] Add save, compare, export, review, correction, and replay workflows.
- [ ] Establish model-specific resource profiles and cancellation.
- [ ] Prototype method-specific records for field observation, historical research, and qualitative studies before extracting common abstractions.

## Phase 3 — Hands-on education

- [ ] Add guided lessons and instructor-authored investigation sequences.
- [ ] Teach the nature of science, evidence, uncertainty, bias, and the diversity of scientific methods.
- [ ] Support learner progression from observation to independent investigation.
- [ ] Add classroom / cohort workflows through optional platform integration.
- [ ] Include accessible explanations, units, and uncertainty in every lesson.

## Phase 4 — Research and collaboration

- [ ] Add private workspaces and collaboration.
- [ ] Add checkpointing and long-running execution support.
- [ ] Add reviewed model catalogs and reproducible research exports.
- [ ] Establish expert review and publication workflows for high-consequence models.
- [ ] Support replication, independent review, correction, retraction, and governed open data.

## Phase 5 — Hosted laboratories and monetization

- [ ] Define compute metering, budgets, quotas, and transparent pre-run estimates.
- [ ] Integrate identity, entitlements, and persistent sessions through platform boundaries.
- [ ] Introduce paid private laboratories and institutional offerings.
- [ ] Add creator publishing and licensing only after governance is operational.

## First experiment selection

The first experiment should be chosen after inspecting the actual Physics package, not by inventing a dependency contract. Prefer a bounded investigation that demonstrates the complete lifecycle and produces observable, testable results. The first vertical slice matters more than the spectacle of the first demo.
